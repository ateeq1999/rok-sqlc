# The generated-code quality bar: typed ids, documentation, lints, borrowing, opt-in serde

Generated code is library code the user owns and reads. It should look like a careful person wrote it, and it should never be the reason a consuming crate has to relax its lints. This ADR sets the bar every generated module meets, and the fixture crates enforce it.

**Keys are typed.** A table with a single-column primary key gets a typed id (`ProductId`): a transparent SQLx type with `Debug`, `Clone`, `PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, and `Display`, plus `Copy` when the inner value is `Copy`, and `From` conversions both ways. The key column, every foreign key column referencing it, and every generated function taking the key use it, so passing a `CategoryId` where a `ProductId` is expected is a compile error. A composite key gets a key struct (`OrderItemKey`) with a `key()` accessor on the row; lookups and `search_after` cursors take it. Query-file functions follow the same rule where the SQL settles it: a parameter typed by a key or foreign key column, and a result column taken straight from one, use the typed id; a parameter compared with two different ids, and any computed expression, keep the plain type, since rok-sqlc cannot tell which id was meant. Typed ids are resolved over the tables generated together, so a foreign key to a table outside the run keeps its raw type. Generated types are not `#[non_exhaustive]`: the user owns the schema they come from.

**Every public item is documented**, so a consuming crate can `#![deny(missing_docs)]`. Each generated module file has an inner doc; a resource's submodules are documented where `mod.rs` declares them. Row, input, patch, and key fields name their column; filter fields say which column they constrain; enum variants show their exact database value; query rows and parameter structs document each column or placeholder.

**Generated code passes `cargo clippy -- -D warnings`** with the default lints plus a selected set of pedantic lints:

`default_trait_access`, `doc_markdown`, `explicit_iter_loop`, `implicit_clone`, `items_after_statements`, `manual_let_else`, `match_same_arms`, `missing_panics_doc`, `must_use_candidate`, `needless_pass_by_value`, `redundant_closure_for_method_calls`, `ref_option`, `return_self_not_must_use`, `semicolon_if_nothing_returned`, `single_match_else`, `trivially_copy_pass_by_ref`, `uninlined_format_args`, `unnecessary_wraps`.

Both fixture crates (`tests/fixture-app`, the hand-written fixture, and `tests/modules-app`, the module corpus) declare `#![deny(missing_docs, warnings)]` and these lints, and their harnesses run `cargo clippy --all-targets -- -D warnings`, so any generator change that falls short fails the test suite.

**Parameters are borrowed where that is natural.** `Copy` values (integer, UUID, date and time keys, their typed ids, and enums) are taken by value. Text is borrowed: a text key is `&str`, or `&` its typed id (`&CurrencyId`); a key struct with a text column is taken as `&OrderItemKey`, and the `search_after` cursor as `Option<&…>`. Positional query-file parameters take `&str` for text and slices (`&[T]`) for arrays, also inside `Option`. Binding a borrowed value is as cheap as binding an owned one, so the caller never clones just to call a function. Inputs (`NewX`), patches (`UpdateX`), filters, and query parameter structs stay owned: they are built for the call and moved into it.

**`serde` is opt-in.** `derive = ["serde"]` (in `rok-sqlc.toml`, the JSON payload, or `-d/--derive serde`; `Config::derive` with `Derive::Serde` in the library) adds `serde::Serialize` and `serde::Deserialize` to rows, typed ids, key structs, enums, inputs, patches, joined-read structs (`ProductWithCategory`), query rows, and query parameter structs. Typed ids are `#[serde(transparent)]`, so they serialize as their inner value, and enum variants serialize as their exact database label, so JSON matches what the database stores. The derives join each type's existing derive list (rustfmt merges adjacent derives, and generated code stays rustfmt-clean). The dependency hints in the generated `mod.rs` then list `serde` with its `derive` feature and the `serde` feature of `uuid`, `chrono`, and `rust_decimal` where they are used. Without `derive`, generated code does not mention `serde` at all.

## Considered Options

- **All of `clippy::pedantic`.** Rejected: new pedantic lints arrive with every clippy release, so CI on stable would break with no generator change; and several pedantic lints argue with deliberate choices (`missing_errors_doc` on every function returning `sqlx::Error`, `needless_raw_string_hashes` on SQL that is always in `r#"…"#` so editing it never changes the delimiter, `large_types_passed_by_value` on inputs we decided to move). A fixed list states exactly what the bar is.
- **Borrow every non-`Copy` parameter.** Rejected: inputs, patches, and filters are consumed values a caller builds for one call; taking them by reference would force a clone inside, or tie their lifetime to the query.
- **Take a text typed id by value, like other typed ids.** Rejected: a `String` key is not `Copy`, so callers would clone to keep using it.
- **`serde` on by default.** Rejected: it would add a dependency (and feature flags on `uuid`, `chrono`, `rust_decimal`) to every consuming crate, most of which never serialize rows directly.
- **`serde` on filters and search types.** Deferred: they are query inputs, not data; nobody has asked to send a filter over the wire.
- **A patch's `Option<Option<T>>` with `serde_with`'s double-option.** Deferred: with plain serde, `Some(None)` ("set to NULL") and `None` ("leave unchanged") both serialize to `null`, so a deserialized patch cannot set a column to `NULL`. Callers who need that build the patch in code.
