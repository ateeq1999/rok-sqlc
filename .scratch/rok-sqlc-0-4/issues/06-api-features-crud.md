# 06: API features: layout, services, and CRUD

**What to build:** The heart of ADR 0016. For every generated table not in `api.exclude` (join tables excluded), generate the feature under `api.output/<module>/`.

**The eight files:**

| File | Contents |
|---|---|
| `mod.rs` | re-exports `routes`, the service struct, and the trait |
| `routes.rs` | `pub fn routes(cfg: &mut web::ServiceConfig)`: one `web::scope(<prefix><route base>)` |
| `handlers.rs` | `list`, `create`, `get_one`, `update`, `remove`: parse, call one service method, return |
| `dto.rs` | `CreateUserDto` (validated like `NewUser`), `UpdateUserDto` (all optional, validated like the patch), `UserResponse` (`From<User>`), `ListUsersQuery` |
| `model.rs` | re-exports the rows and typed ids from `db` |
| `repo.rs` | re-exports the table's `db` functions |
| `service_api.rs` | the `UsersServiceApi` trait, native `async fn` |
| `service.rs` | scaffolded: `pub struct UsersService { pub pool: PgPool }` and `impl UsersServiceApi for UsersService { fn pool(&self) -> &PgPool { &self.pool } }` |

**The service trait:** each write endpoint has a `create_in(&self, conn: &mut PgConnection, …)` holding the logic and defaulting to `db`, and `create(&self, …)`, which opens a transaction, calls `_in`, and commits. Reads take `&self` and use the pool. Everything returns `Result<_, AppError>`.

**Root files:**
- `api.output/generated.rs` (regenerated) declares each feature with `#[path = "users/mod.rs"] pub mod users;`. It also holds `pub fn register_services(cfg, pool)` (`app_data` per service) and `pub fn configure_all(cfg)`.
- `api.output/README.md` (regenerated) maps which files are generated and which are yours.

**Endpoints:** route base is the kebab-case module name, overridden by `api.routes`, under `api.prefix`:
- `GET /` with `?page&per_page&q&sort&order` → `{items, page, per_page, total}`. `q` uses ILIKE, escaped, over the `api.search` columns. `sort` is over `api.sort` (default: the primary key, plus `created_at` if present), generating `XSort`. New `db` functions may be needed; add them in the data layer.
- `POST /` → 201 with `Location`.
- `GET /{key…}`, `PATCH /{key…}` and `DELETE /{key…}` (204). Composite keys go in the path in order. A table without a key gets only list and create.
- `api.skip` drops endpoints and their trait methods.

**Errors** go through `AppError` per the wire standard.

**Tests:** a new fixture crate `tests/api-app` (actix-web 4, generated with `api.output` from a schema covering a UUID key with `uuid_v7`, a composite key, a key-less table, search and sort config, and a skip). Its tests use `actix_web::test` against PostgreSQL: status codes and bodies for every endpoint and failure, paging metadata, `q`/`sort`, and a service override in the scaffolded `service.rs` surviving regeneration. Add the regeneration scenario: a schema change adds an endpoint and the user's file stays untouched. Wire it into `tests/fixture_compile.rs` like the other fixtures (lint gate included). Also include an end-to-end compile check of `rok-sqlc init` plus generation.

**Blocked by:** 05

- [x] Scaffolded `service.rs` overrides survive regeneration and a schema change, and output without `api.output` is unchanged.

## Comments

Resolved on branch `rok-sqlc-0-4-06`.

**Generator.** `src/generator/api/` (ticket 05's `api_shared.rs` moved in as `api/shared.rs`): `feature.rs` (the model), `listing.rs` (data layer), `dto.rs`, `service.rs` (`service_api.rs` and the scaffolded `service.rs`), `handlers.rs` (`routes.rs`, `handlers.rs`), `files.rs` (`mod.rs`, `model.rs`, `repo.rs`), `root.rs` (`generated.rs`, `README.md`), `layout.rs` (rustfmt layout helpers).

**What a feature looks like** (`notes`, key `NoteId`): `pub trait NotesServiceApi { fn pool(&self) -> &PgPool; async fn list(&self, query: ListNotesQuery) -> Result<PaginatedResponse<Note>, AppError>; async fn create_in(&self, conn: &mut PgConnection, input: CreateNoteDto) -> Result<Note, AppError>; async fn create(&self, input: CreateNoteDto) -> …; get_one(id), update_in/update(id, UpdateNoteDto), remove_in/remove(id) }`, native `async fn` with `#[allow(async_fn_in_trait)]`. Services take the DTOs and return rows; handlers map rows to `NoteResponse`. Handler: `pub async fn get_one(service: web::Data<NotesService>, path: web::Path<NoteId>) -> Result<HttpResponse, AppError>`. Composite keys are `web::Path<XKey>` with `/{col_a}/{col_b}`; a single key is `/{id}`.

**Decisions.**
- **Stale files:** a run with `api.output` also walks `api.output` and `shared/` (`generator::api_owned_dirs`) and removes generated files (`// @generated` or the Markdown `<!-- @generated by rok-sqlc` marker, which the writer now recognizes) that nothing plans: a dropped table's feature files, a retired shared tool. Scaffolded files (`service.rs`) and the user's own files are never stale; a dropped table's folder keeps its `service.rs`, no longer declared by `generated.rs`. `--check` reports them. Dropping `[api]` entirely can't know `api.output`, so only `db/pool.rs` goes (as before).
- `service.rs` has `XService::new(pool)`, and `register_services` calls it (not a struct literal), so a user can add fields (ports) without breaking regenerated code. Deviation from the ticket's literal.
- `CreateXDto` leaves out a key the server makes (`primary_key_ids`); the server always makes it.
- List: `q` over `[api.search]` (ignored without search columns, empty `q` = no filter), `ILIKE` with `%`/`_`/`\` escaped via the new `search::push_contains_any`; `sort` over `[api.sort]` or the key columns plus `created_at` (or the first sortable column); default sort `created_at` if a sort key, else the first; ties by primary key. New data-layer file `db/<table>/listing.rs` (`XSort` with `DEFAULT` and `column()`, `list_matching`, `count_matching`), only for features serving `list`.
- Malformed path or query → `400 bad_request` through `shared::validation::{path_config, query_config}` on each scope; text keys in `Location` go through `shared::response::path_segment`. Well-formed JSON that doesn't fit a body is ticket 01's `422`.
- Tables with a tenant or version column are refused ("add it to `api.exclude`") until 08; soft-delete tables work through the data layer's live-row reads and `delete`. Tables without insert columns get no `create`; without a key or updatable columns, no `update`.

**Seams for 07/08.** `Feature` (`feature.rs`) is built once per table from `ApiConfig` and every renderer iterates `feature.endpoints` (`Endpoint` enum, with `name`, `method`, `takes_key`, `writes`): 07 adds access/owner/hidden fields to `Feature` (extractor params in `handlers::render_handler`, caller args in `service::render_*`, hidden columns filtered in `dto::render_response`, owner left out of `create_columns`); 08 adds `Endpoint` variants (lookups, restore, search, relationships) handled in each renderer's `match`, and lifts the tenant/version refusal in `Feature::of` (`Tenant<T>` param, `ETag`/`If-Match` in the handler, `UpdateOutcome` in `update_in`).

**Tests.** `tests/api-app`: schema of notes (UUID v7 key, unique, checks, search/sort), members (composite text+FK key), audit_events (no key, route `/audit-log`), labels (BIGSERIAL, `remove` skipped), note_labels (join table, no feature), drafts (keyless in `0001`, keyed in `0002`). `tests/notes.rs` and `tests/shapes.rs` cover every endpoint and failure against PostgreSQL (each test in its own schema). The harness generates from `0001` then from both migrations and checks the checked-in, edited `features/drafts/service.rs` is untouched and compiles against the widened trait. Gitignored: generated features, `generated.rs`, `README.md`; `chrono` added to the fixture (lock extended, not regenerated). `tests/api_features.rs`: feature selection, skip, stale removal, refusal, long-name rustfmt. `init_then_generate_builds_end_to_end` (fixture_compile): `init`, a migration, `g`, a `Cargo.toml` built only from the two hint blocks, `cargo build`. It builds; as a binary crate it has `dead_code` warnings for unused data-layer items (not a lint gate; ticket 04/09 may want an allow in the scaffold).
